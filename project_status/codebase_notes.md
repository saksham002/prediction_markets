## Replay own-footprint filter (strip our own orders from a recording) (NEW 2026-06-21)
- **Why**: a recording that contains our own orders (coid-tagged deltas, own fills) would double-count our footprint when replayed — the sim would quote against, and fill on, our own resting qty. Strip the footprint so such a recording re-sims cleanly.
- **Recording format (verified)**: the recorder writes ALL channels VERBATIM to the SAME per-game `dataset/<event>.jsonl.gz` (NO separate fills file). Own `orderbook_delta`s carry `client_order_id`; own `fill`s + the matching public `trade` share a `trade_id`; **`orderbook_snapshot` is aggregated `[price, qty]` per side with NO `ts_ms` and NO per-order tag** — so own qty in a snapshot can only be removed by reconstruction.
- **Filter (`replay.py`, `Replayer(filter_own=True)`, default on)** — keeps BOTH the book and the fill-engine/alpha market-only: (1) pre-scan marks own fill `trade_id`s (`view.mark_own_fill`); (2) skip `orderbook_delta` where `view.is_own_delta` (has `client_order_id`); (3) skip `trade` where `view.is_own_trade` (`trade_id` ∈ own fills); (4) reconstruct the own resting qty from the skipped own deltas (`_own_resting`) and SUBTRACT it from aggregated snapshots (`_strip_own`) before `apply_snapshot`. Reuses the self-feed primitives. **Gated → bit-identical for clean games** (no own tags → nothing marked/subtracted; canary KORCZE still MATCH −197.0956/23). Inherent limit: removing own orders assumes other participants' behaviour was independent of our presence (no true counterfactual).
- **Exchange-time monotonicity — checked ALL 31 WC recordings, NOT an issue**: exchange `ts_ms` is strictly monotonic in recording (local) order (0 delta inversions, max-backward 0ms, 0 stale snapshots). Deltas are incremental → commute; only snapshots overwrite, and none are stale → **overwrite-on-snapshot is correct; no reordering/re-apply handling needed** (verified before building it, per "check first").
- **Dataset grew 27→31 WC games** (Jun20/21 added ECUCUW, GERCIV, NEDSWE, TUNJPN). The completed agg_dev sweep used the 27-game snapshot (21/6 split); `wc_games()[:N_TRAIN]` on the current 31-game set would split 21/10 — bump `N_TRAIN` or pin the game list before any re-run.
- **Env-overridable paths (`research/hft/paths.py`, NEW)**: all HFT filesystem roots (`HFT_DATA`/`DATASET`/`SIMS`/`STUDIES`/`TICKS`) derive from `KALSHI_HFT_DATA` (default `/data/user_data/saksham3/kalshi_hft`). Every `research/hft/*.py` imports its roots from here instead of hard-coding (core files use `from research.hft.paths import …`; standalone-run scripts like `espn_clock` use a `try research.hft.paths / except paths` dual import). Off-Babel: `export KALSHI_HFT_DATA=/local/path`. Only docstrings + `paths.py`'s own default still contain the literal Babel string. (Not touched: `research/arbitrage/` + `research/signals/` use a separate `/data/.../kalshi/` base; sbatch `#SBATCH` dirs are SLURM-static.)
- **Legacy alpha config path REMOVED (2026-06-21)**: `StrategyConfig.from_params` now REQUIRES an `alphas` list (raises otherwise); `ensure_alphas(params)` bridges the `-a/-t` CLI shorthand into a 1-gate list at the boundary; `--config` loaders hard-fail on a config without `alphas`. All callers migrated. Canary stays bit-identical (−197.0956/23). See the StrategyConfig section below.

## Fractional order sizes + exchange-ack logging (NEW 2026-06-20)
- **Fractional contracts**: Kalshi supports **fractional contracts, min 0.01**; `count_fp` is a literal decimal contract count, NOT ×100; KXWCGAME is fractional-enabled, and counterparties can fill an order fractionally (e.g. a count=200 order filled as `[199.77, 0.23]`). `ProdExchange._do_place` sent **`int(qty)`** to `create_order`, so a 0.99 dust-reduce became `count="0.00"` → rejected → re-quoted forever (acks/rejects were never persisted, so this was hard to see). See memory [[kalshi-fractional-contracts]].
- **Fix (fractional)**: `_do_place` now sends `count = round(qty, 2)` (≥0.01 granularity) and stores that count on the `_ProdRestingOrder`. `api.create_order`'s `count` hint `int`→`float` (body already formats `f"{float(count):.2f}"`, so it was always fractional-capable; only the `int()` caller defeated it). Counterparties fill fractionally regardless of our size, so flooring to whole contracts would NOT stop dust — sending the fraction clears it.
- **`_budget_clip` floor-divide → normal divide (`mm_sim.py`)**: `affordable = (budget - deployed) // price` truncated the budget cap to whole contracts; now `/ price` so an entry can use the fractional remainder of the budget. CHANGES sim PnL when the cash budget binds (no longer bit-identical to the floor-div baseline — intended). Edge case: when budget is within ~½¢ of exhaustion an entry can produce a 0.01-contract order where floor produced none (immaterial). This was the only quantity-related `//` in the codebase (others are ms→s ts, median list-index, batch-id, JS comments).
- **Exchange-ack logging (closes the observability gap)**: new **`acks.jsonl`** log (same IPC-queue→logger path as `orders.jsonl`). `MMSimConsumer._deliver` now calls `_log_ack(result, msg)` for both `ack` and `reject` (exchange-backed path only — guarded by `self._timing`); the logger routes `type=="ack"` → `acks.jsonl` (`live_ipc.ACKS_LOG`, `live_logger` `dest` map). Ack record: `result(ack|reject), read_ts, exchange_ts, op(place|cancel), leg, side, client_order_id, order_id, status, err`. Reject `_emit`s in `_do_place`/`_do_cancel` were enriched with `market_ticker`/`side`. **Order records now carry `client_order_id`** (threaded through the `on_order` hook: `order_router.place/cancel` → `_log_order_timing`) so orders ↔ acks ↔ fills all join on coid.
- **Tests**: `tests/{test_exchange,test_order_router,test_live_mm}.py` pass (30); full `tests/` 60 pass, 4 pre-existing failures in `test_trade_fill_ma.py` (unrelated momentum signal). `on_order` is untested; sim path unchanged (sim sets `on_order=None`, `self._timing=None`).

## Stop quoting on market resolution (ProdExchange) (NEW 2026-06-19)
- **Why**: the exchange-backed path had NO market-lifecycle awareness — past 85' `WCStrategy._phase` returns `"liquidate"` forever (no terminal phase), so after the final whistle the strategy would keep quoting into a closing/finalized market (rate-limited reject loop; relying only on the `--duration` timeout + book/spread guards to go quiet). Sim never sees this (replay just ends).
- **Fix**: `ProdExchange.run` now also subscribes to the **`market_lifecycle_v2`** WS channel (id 3, firehose — the channel takes no `market_tickers` filter, so we filter client-side). `_dispatch` routes `type=="market_lifecycle_v2"` → `consumer.on_market_lifecycle(msg)`. On `event_type` in **`determined`/`settled`** for a market we quote, `MMSimConsumer.on_market_lifecycle` adds EVERY leg of the owning strategy to `self.closed_markets` and `router.set_target(...,None)` both sides (cancel any resting). `on_book`/`on_trade` skip `mm.requote` when `ticker in closed_markets` → the market is never quoted again. `determined` carries `result` (yes/no) + `settlement_value` (fixed-pt $) — logged, not used for stop. `deactivated` is NOT treated as terminal (can be a transient pause; book guards already suppress quoting a halted book).
- **Bit-identical preserved**: `closed_markets` is empty in sim (replay emits no lifecycle msgs) → the requote skip is always-False. Verified KORCZE REALISTIC_DELAYS still `−61.1833 / 229`. Tests: `test_exchange.py` +2 (`test_dispatch_routes_market_lifecycle`, `test_lifecycle_determined_closes_market_and_cancels`).

## OrderRouter is now DESIRED-STATE + ProdExchange is ASYNC non-blocking (NEW 2026-06-19)
- **Why**: "cancel + new" blocked all processing on the exchange-backed path — the strategy self-blocked on the in-flight lock AND `ProdExchange.place/cancel` made SYNCHRONOUS `requests` REST calls on the asyncio loop thread (a full REST round-trip of WS blindness per cancel-replace).
- **Desired-state router (`order_router.py`)**: the strategy is now UNAWARE of in-flight / pending-ack / rate-limit state. It calls `router.set_target(lts, ticker, side, want, ctx)` (`want`=(price,qty) or None) — that's the ONLY ordering call. The router owns the in-flight lock, the `WriteRateLimiter` budget, the passive-level invariants (`view.depth` supported / >0 / `max_queue`), and the order logging. `set_target` stores the target+ctx and calls `reconcile(lts,t,s)`, which runs the EXACT old `_reconcile_side` per-side logic (same order, gates, inline place-after-cancel via the backend drain) — so the sim is **bit-identical**. `reconcile_all(lts)` is a ProdExchange-only sweep. `on_ack`/`on_private_fill`/`on_reject` are STATE-ONLY (no reconcile → no re-entrancy); the deferred place is picked up by the next event's pre-requote `exchange.drain` + reconcile (sim) or the ack-completion's explicit reconcile + the periodic timer (ProdExchange). The strategy's `_reconcile_side` is now a one-line `set_target` delegator; `WCStrategy._cancel_all` is `set_target(...,None)`. Watchdog's old `reconcile_side(t,s,resting)` renamed → **`force_state`** (disambiguated from the drain-loop `reconcile`).
- **Handles the asks**: rate-limited cancel+new → cancel sent, place deferred until budget frees (target persists, retried by reconcile/reconcile_all); price changed while a cancel is in flight → the cancel-ack's reconcile reads the LATEST target → places the NEW price, never the stale one.
- **ProdExchange async (`exchange.py`)**: `place/cancel` mint the coid, fire the blocking REST in a BACKGROUND task (`asyncio.create_task(_do_place/_do_cancel)` → `asyncio.to_thread(api.create_order/cancel_order)`) and return IMMEDIATELY — the WS `async for` is never stalled. On completion (on the loop): record the handle, `_emit` the ack/reject, and (ack only) `reconcile(now,t,s)` off the latest target (reject does NOT reconcile inline → no 429 storm; the periodic `_reconcile_timer` ~50ms is the deferral safety net). `place` returns `(None, coid)` (handle unknown until the ack); the router tracks by coid and reads the resting order via the new `backend.resting_for(coid)` (Sim: fill-engine order, identity-preserving; Prod: `_orders[_coid_to_handle[coid]]`). `run()` stores `self._consumer` for the callbacks.
- **Bit-identical VERIFIED** (refactor == pre-refactor baseline, KORCZE obi_dev_60s): delays=0 `net -21.6255 / fills 163`; REALISTIC_DELAYS `net -61.1833 / realized -14.5797 / fees 14.14 / fills 229` (also MEXRSA `-20.0476 / 41`). NB `scratch/verify_bitident.py`'s hardcoded `317.4560/575` is STALE — it pre-dates later commits (`33fe652` size-clip, `388543a` position-sign) that legitimately moved PnL; the CURRENT baseline is `-61.1833/229` and the refactor matches it exactly. Tests: `test_order_router.py` (11, +5 desired-state behavior) + `test_exchange.py` (15, +async-prod non-blocking) pass. The taker/aggro path (`_aggro_entry`/`_take`) is unchanged (still inline fill-sim, not routed through the exchange backend) — out of scope, see todos.

## Kalshi V2 order endpoints + recorder fill channel + per-game metric (NEW 2026-06-18)
- **V2 order migration (`src/utils/api.py`)** — Kalshi removed the V1 `/portfolio/orders` mutation endpoints (Jun 2026; `POST`→`410 deprecated_v1_order_endpoint`). `create_order`/`cancel_order` now hit **`POST`/`DELETE /portfolio/events/orders[/{order_id}]`**. The call signature is UNCHANGED (`side`='yes'/'no' + `action`='buy'/'sell' + `price_cents`): internally translated to V2's **YES-leg `bid`/`ask`** (`bid`=buy yes, `ask`=sell yes; buy no == ask @ the yes-equiv price) + fixed-point string `price`/`count` + required `time_in_force` (`good_till_canceled`) and `self_trade_prevention_type` (`taker_at_cross`); optional `post_only`. **V2 response is FLAT** → `resp.json()["order_id"]` (`ProdExchange.place` updated; was `["order"]["order_id"]`). Read endpoints (`GET /portfolio/orders|positions|fills|balance`) are UNCHANGED. We don't use amend/decrease/batch (batch tokens would be create 10/order, cancel 2/order).
- **Position from the fill, not `market_positions`** — `_on_fill_reduce` sets inventory to the fill's authoritative `post_position_fp` (and `logger.warning`s if the incremental compute disagrees — drift/missed fill). The `market_positions` WS subscription/overwrite was REMOVED (a stale msg after a newer fill could revert position; can't dedupe generically). `SimExchange` tracks signed net (`_sim_pos`) and stamps the real `post_position_fp` on synthetic fills → sim stays bit-identical.
- **Recorder also logs the private `fill` channel** (`record_ticks.py`) — recordings carry which trades/orders are the account's own: match a public `trade.trade_id` to the private fill's `trade_id`; own `orderbook_delta`s already carry `client_order_id` (recorder writes raw frames verbatim, so these tags persist). `replay.py` silently skips `fill`-type lines (no `else` branch) → datasets/sweeps unaffected.
- **Filtering own orders out of the market replay** — fully achievable: own deltas (place/cancel; fill-reduction unconfirmed but place+cancel ARE tagged) → drop/subtract by `client_order_id`; own public trade prints → identify by matching `trade_id` to own `fill`s. Does NOT depend on the fill-reduction-delta carrying the coid.
- **Per-game metric is the reporting standard** — `wc_sweep.py` `_agg` SUMS net across games (IN ~20, OUT ~4 games), so always divide by the game count and compare per-game IN vs OUT (summed totals over-weight the tiny OOS sample). See memory [[feedback-per-game-metric]].

## SimExchange: sim mirrors the exchange self-feed; `live` flag removed (NEW 2026-06-17)
- **`research/hft/exchange.py` (`SimExchange`/`ProdExchange`)** — the sim now INJECTS our own order lifecycle into the SAME public+private feed messages the exchange emits, so the consumer processes its own orders identically in both backends. The book + message stream already contain our orders → **the `live` flag is GONE; one unified path**. `MarketView` reads always subtract the own-resting ledger; with an empty ledger (analysis callers that never place) reads == raw (behaviour-neutral).
- **Message shapes (from captured feed messages)**: PLACE→public `orderbook_delta`(δ>0, client_order_id) + private REST ack; FILL→public `orderbook_delta`(δ<0, client_order_id) + public anonymous `trade`(trade_id) + private `fill`(trade_id+order_id+client_order_id+post_position_fp); CANCEL→public `orderbook_delta`(δ<0) + private ack. Match key public-trade↔private-fill = `trade_id`; the maker side = OPPOSITE public taker_side. Synthetic ids are `SIM-{COID,OID,TRADE}-N` (deterministic; can't collide with real UUIDs).
- **Flow: `Replayer → SimExchange (owns PassiveFillEngine + delay scheduler) → consumer feed handlers (_deliver) → MarketView/OrderRouter`.** SimExchange merges recorded market messages with our scheduled own messages in effective-time order; the consumer is purely feed-driven (`on_public_delta`/`on_public_trade`/`on_private_fill`; `_on_fill_reduce` is the single inventory/PnL path off the authoritative private fill).
- **No requote gate (NEW 2026-06-17): EVERY event updates the view, then the strategy re-decides from it.** Removed the `moved`/`rest_emptied`/`_last_quote` special-case gate in `on_book` (it also missed obi changes from deep-book deltas that don't move the touch). `_reconcile_side`'s market-only `supported = is_pos(view.depth(...))` is the SOLE, view-driven mechanism: an order at a level whose remaining MARKET backing is 0 (only our own qty) is pulled — no hand-coded trigger. on_book now mirrors on_trade (always requote). Costs ~2x (alpha recompute every event) but is the correct model. NOTE: this re-bases the delays=0 numbers vs the gated equivalence baseline (more requotes) — orthogonal to the self-feed exclusion, which the per-tick invariant validates gate-independently.
- **OrderRouter in-flight lock (always on)**: per (ticker,side) state IDLE→PLACE_INFLIGHT→RESTING→CANCEL_INFLIGHT; one outstanding action per side (a 2nd is blocked while unconfirmed). Ledger is message-based (reads the public own-delta), deduped by trade_id.
- **Unified exchange API — ProdExchange is symmetric with SimExchange (NEW 2026-06-17)**: both share the EXACT same backend API (`place`/`cancel`/`drain`/`orders`/`own_levels`/`on_recorded_*`) so the consumer/router/strategy are byte-for-byte identical across backends. The ONLY differences are internal: **SimExchange** replays + simulates fills (PassiveFillEngine + delay scheduler); **ProdExchange** drives the exchange WS (`async run(consumer)` subscribes public `orderbook_delta`+`trade` and private `fill`) and sends REST orders (`src/utils/api.py` `create_order`/`cancel_order`). `exchange.simulates` (True/False) is the single branch in the consumer — gates snapshot re-injection (sim re-injects our qty into market-only recorded snapshots; an exchange snapshot already includes our orders). **ProdExchange does NOT model the queue** (`fill_engine=None`, `on_recorded_*` no-ops): fills come from the authoritative private `fill` channel. `_ProdRestingOrder.queue_ahead=0`. Confirmations: REST 2xx → synchronous ack (via `_deliver`), public own-delta + private fill arrive on the WS; reject/429/network-error → `_deliver("reject")` → `router.on_reject` frees the side. `live_mm.py --live` selects the ProdExchange backend (default = paper: LiveFeed drives SimExchange, no orders sent). **Edge cases handled (B)**: order reject (`on_reject`→IDLE, no PLACE_INFLIGHT deadlock), 429 rate-limit (reject→retry), cancel/fill race (a fill in CANCEL_INFLIGHT frees the side; full-fill detected by cumulative-fill vs order qty — backend-agnostic), 404-on-cancel (already filled → treat as cancelled), reconnect (`reconcile()` cancels ALL resting orders for a clean slate + resets ledger).
- **Token rate limiter (`WriteRateLimiter`, NEW 2026-06-17)**: budget 100 tokens/rolling-sec, place=10, cancel=2. `try_place`/`try_cancel`.
- **Trade-flow (D3): alpha sees C.** Our fill is additive (others still get the full replayed C; total public = C+q); the recorded trade flows to the alpha UNCHANGED and our fill is emitted as a synthetic public trade tagged-excluded (mark_own_fill) → alpha = C. Identical to the old sim for flow alphas too.
- **CRITICAL clamp (commingling bug fix)**: a recorded MARKET delta must reduce only the MARKET portion (clamp at 0) — never below our own resting qty (`MarketView.apply_delta(is_own=False)`; recorded deltas routed through it in replay.py). Without this, a market-only reduction whose magnitude exceeds the market portion drains our commingled order. Mirrors the exchange (a participant's cancel removes only their depth).
- **Feed delays (D4, `exchange.REALISTIC_DELAYS`)**: constant, configurable. Default **0** (synchronous = equivalence baseline, lock non-binding). REALISTIC = ack 22ms / pub 28ms / fill 16ms; the lock then binds and cancel-replace costs a round-trip. Real delays are variable (not modeled). For a FILL the private+public arrive together ~16ms after the match (`fill_delay`), priv→pub gap ~0.
- **Equivalence validated (delays=0)**: best config (obi_dev_60s) across all 20 WC games — **19/20 net/realized/fees/fills/contracts BIT-IDENTICAL** to the pre-change baseline; HTISCO net off by 1e-4 (sub-cent float-ordering in the unrealized mark; realized/fills/fees/contracts identical). ## MarketView + OrderRouter refactor (NEW 2026-06-17) — self-feed correctness

## Float-comparison robustness (feps.py) — NEW 2026-06-16
- **`src/utils/feps.py`**: shared residue-robust comparison helpers — `EPS = 1e-6`; `is_zero / is_pos / is_neg / gt / lt / gte / lte` (each takes optional `eps=`). Use for ALL quantity / inventory / depth comparisons against a threshold (usually 0); NOT for price ticks.
- **Why**: fractional contract sizes accumulate float error under repeated add/subtract, so a logically-0 size lands at e.g. 1e-13; `== 0` / `> 0` / `<= 0` then misfire (phantom position, a book level that looks alive, an order that never clears). The old ad-hoc fixes (`orderbook <= 1e-9`, `mm_sim inv > 1e-9`) were inconsistent and too small.
- **Applied codebase-wide**: orderbook.apply_delta/load_snapshot, pnl.trade (phantom-position guard at remaining/leftover), passive_fill (remaining/overflow/fill_qty/pending), mm_sim (inventory `==0`/`>0`/`<0`, the displayed-backing guards, qty), alphas `_depth`/`market_obi`/`_best_bid_ex`, agg_flow_ma pending. Tests: `tests/test_feps.py`.
- **Empirically validated (scratch/size_audit.py on BRAMAR, the highest-volume game, 694k deltas)**: book level sizes split cleanly — **max float residue 3.5e-7 < EPS 1e-6 < smallest real size 0.01**. Kalshi book levels DO hold real fractional sizes (clean 2-decimals: 0.01, 0.25, 0.5, 0.6, …), so EPS must stay ≪ 0.01; 1e-6 pops only residue. **Impact is material, not cosmetic**: the old 1e-9 left residual phantom levels (~1e-7) that saturated obi toward ±1.0 and inflated agg level-factors — fixing it shifted obi/agg threshold distributions (obi p90 1.0→0.90) and PnL (obi/KORCZE 244→302 net); trade-based tfma was unchanged (doesn't read book levels), which confirmed the book was the source.

## Invariants / gotchas
- Books: price keys are 4-decimal dollar strings; BookSide caches best (rescan only when best level empties).
- **obi cache (2026-06-17; key completed 2026-06-19)**: `BookSide._ver` is a monotonic mutation counter bumped at the TOP of `apply_delta`/`load_snapshot`; `alphas.py` `_obi`/`_pair_obi` memoize on the book-version tuple. INVARIANT: any new code path that mutates `BookSide.levels` MUST go through apply_delta/load_snapshot (or bump `_ver` itself) or the obi cache returns stale values. Valid because market-only obi is invariant to own deltas → cache == recompute (verified bit-identical, ~16.5% faster). **2026-06-19 fix**: the cache key was INCOMPLETE — market-only obi = book MINUS the own-ledger, but the token was book-`_ver` only, so a `view.register` WITHOUT a paired book delta (e.g. a standalone `register_resting`) left obi stale (`test_register_resting_excludes_own_qty_from_obi` failed). Added a per-(ticker,side) own-ledger version (`MarketView._own_ver`, bumped in `register`; `view.own_ver(t,s)`) to BOTH obi tokens. In the real self-feed flow register is always paired with `apply_delta(is_own=True)` (book `_ver` already bumps), so this only ADDS invalidations there → recompute returns the same value → **bit-identical** (re-verified KORCZE SingleMM −61.1833/229 AND two MLB PairMM games unchanged pre/post).
- Trade msg: maker side = opposite of taker_side at the maker price; ts_ms = Unix ms match time (verified +19ms median vs local).
- Splits: test = md5(event)%5==0; val = md5("val"+event)%5==0 among non-test. NEVER split by row (180s windows overlap).
- PnL: per-ticker attribution (realized_by_ticker/fees_by_ticker); same-market YES+NO nets to $1 (verified); `--resolve` settles at official results.
- Replay perf: ~3s per game per config (was 48s; fixes: lazy alphas, quote-move gating, best-bid cache, nlargest).
- Recordings: jsonl.gz lines {lts, d|meta}; meta has pairs[] + events[] with fee annotations; gzip tail may be corrupt mid-write (replay tolerates).
- sbatch on babel: every job needs --gres=gpu:1; QOSMaxGRESPerUser counts all running GPU jobs.
